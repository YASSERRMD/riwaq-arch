# LLM Setup Guide for Riwaq Arch

Riwaq Arch uses Large Language Models (LLMs) to generate documentation and answer questions about your codebase. It is designed to be compatible with any OpenAI-style API.

## supported Providers

Riwaq supports any provider that adheres to the OpenAI Chat Completions API format.

### 1. OpenRouter (Recommended)
Access to GPT-4, Claude 3, Llama 3, Mistral, and more through a single API.
- **Endpoint**: `https://openrouter.ai/api/v1`
- **Models**: `openai/gpt-4-turbo`, `anthropic/claude-3-opus`, `meta-llama/llama-3-70b-instruct`, etc.

### 2. OpenAI
- **Endpoint**: `https://api.openai.com/v1`
- **Models**: `gpt-4-turbo`, `gpt-3.5-turbo`

### 3. Z.ai (Zurich AI)
- **Endpoint**: `https://api.z.ai/v1` (check provider docs)
- **Models**: `glm-4`, etc.

### 4. Local Models (Ollama / LocalAI)
You can run models locally and use them with Riwaq if they expose an OpenAI-compatible endpoint.
- **Endpoint**: `http://localhost:11434/v1` (for Ollama)
- **Models**: `llama3`, `mistral`

## Configuration

The primary way to configure the LLM is via **Environment Variables**.

### 1. Set Environment Variables

You must set `RIWAQ_LLM_API_KEY`. The endpoint and model have defaults but should likely be configured.

#### macOS / Linux
```bash
export RIWAQ_LLM_API_KEY="sk-..."
export RIWAQ_LLM_ENDPOINT="https://openrouter.ai/api/v1"
export RIWAQ_LLM_MODEL="meta-llama/llama-3-70b-instruct"
```

#### Windows (PowerShell)
```powershell
$env:RIWAQ_LLM_API_KEY="sk-..."
$env:RIWAQ_LLM_ENDPOINT="https://openrouter.ai/api/v1"
$env:RIWAQ_LLM_MODEL="meta-llama/llama-3-70b-instruct"
```

### 2. Running with Configuration

When starting the server or running CLI commands, ensure these variables are set in your shell.

#### CLI Example
```bash
RIWAQ_LLM_API_KEY="sk-..." riwaq ask --path . --question "Explain the authentication logic"
```

#### Server Example
```bash
export RIWAQ_LLM_API_KEY="sk-..."
riwaq serve --port 9527
```

### 3. VS Code Extension Setup

Since the VS Code extension communicates with the locally running `riwaq serve` process, you have two options:

1. **Start the server manually** in a terminal where the environment variables are set, then reload VS Code.
2. **Set environment variables globally** for your user session so VS Code inherits them if it starts the server (future feature).

*Currently, we recommend running `riwaq serve` in a dedicated terminal window with the keys configured.*

## Testing Your Setup

To verify your LLM configuration is working:

```bash
riwaq ask --path . --question "Hello, are you working?"
```

If successful, you will receive a response generated by the model.
